# Домен ekaterinakrainiuk.ru

Основной адрес сайта: `https://ekaterinakrainiuk.ru/`. `www.ekaterinakrainiuk.ru` — дополнительный вход с перенаправлением на основной адрес. Настройка согласована владельцем 7 октября 2026 года.

## GitHub Pages

Репозиторий: `anton-gorokhovatsky/ekaterinakrainiuk`. В **Settings → Pages → Custom domain** используется `ekaterinakrainiuk.ru`. Публикация остаётся через GitHub Actions: job `deploy` получает проверенный артефакт из job `check`. Для этого способа публикации отдельный файл `CNAME` не требуется; домен хранится в настройках Pages.

Домен добавлен также в **настройки аккаунта → Pages** для подтверждения владения. Пока TXT-запись не появилась в DNS и не нажата кнопка **Verify**, статус остаётся неподтверждённым. Подтверждение привязывает домен к аккаунту `anton-gorokhovatsky`; его нужно учитывать при возможном переносе сайта в другой аккаунт.

## Записи DNS в NIC.RU

Домен должен быть делегирован на DNS-серверы той услуги NIC.RU, в которой сохранены записи. 7 октября в панели выбраны `ns3-l2.nic.ru`, `ns4-l2.nic.ru`, `ns8-l2.nic.ru`, `ns4-cloud.nic.ru`, `ns8-cloud.nic.ru`; NIC.RU принял заказ на смену серверов. Прежние `ns3.nic.ru`, `ns4.nic.ru`, `ns8.nic.ru` ещё могут возвращаться до обновления делегирования. IP GitHub из таблицы относятся к A/AAAA и не являются DNS-серверами для полей NS.

Записи добавляются в зону `ekaterinakrainiuk.ru`. Ниже указаны относительные имена: `@` обозначает корень зоны; если форма принимает полное имя, использовать `ekaterinakrainiuk.ru`. TTL — 3600 секунд либо значение по умолчанию в панели.

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| AAAA | @ | 2606:50c0:8000::153 |
| AAAA | @ | 2606:50c0:8001::153 |
| AAAA | @ | 2606:50c0:8002::153 |
| AAAA | @ | 2606:50c0:8003::153 |
| CNAME | www | anton-gorokhovatsky.github.io. |
| TXT | _github-pages-challenge-anton-gorokhovatsky | 0312e2e1465bb1259d93906f87bf84 |

В CNAME указывается имя хоста, без `https://` и без `/ekaterinakrainiuk/`. Завершающая точка обозначает полное доменное имя; если панель добавляет её самостоятельно, повторять её не нужно. A обеспечивают доступ по IPv4; AAAA можно добавить для IPv6. На новых серверах NIC.RU проверены все четыре A, CNAME и TXT; AAAA на момент проверки ещё не возвращались.

Если уже есть A/AAAA для корня или записи для `www`, ведущие на парковку/другой хостинг, их заменить приведёнными выше. MX и почтовые TXT сохраняются; NS должны соответствовать выбранной услуге DNS. Не добавлять wildcard `*`. Проверочный TXT оставить и после подтверждения домена.

Адреса и поведение перенаправлений — по [официальной документации GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Подтверждение — по [инструкции GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages). TXT-код получен из настроек указанного аккаунта для этого домена.

## После добавления записей

1. Проверить A, AAAA, CNAME и TXT через DNS; при необходимости подождать распространения записей. GitHub указывает срок до 24 часов.
2. Подтвердить домен кнопкой **Verify** на [странице подтверждения](https://github.com/settings/pages_verified_domains/ekaterinakrainiuk.ru).
3. Дождаться сертификата GitHub Pages и проверить **Enforce HTTPS** в настройках репозитория. Не считать сертификат полученным только по сохранённому имени домена.
4. Проверить HTTPS на основном домене, перенаправление HTTP на HTTPS, `www` на основной адрес и прежнего адреса GitHub Pages на новый домен.
5. Сверить `release.json` с опубликованным коммитом; проверить главную, изображение шеринга, `robots.txt`, `sitemap.xml` и страницу 404 по вложенному несуществующему пути.

Финальная проверка DNS, сертификата и реального предпросмотра в мессенджере зависит от внесения записей владельцем. Не подменять её локальной проверкой или обращением к GitHub с принудительным IP.

## Индексация и шеринг

На главной снят `noindex`; `robots.txt` разрешает обход. Canonical, Open Graph URL, адреса картинки в Open Graph/Twitter и `sitemap.xml` используют основной HTTPS-домен. На странице 404 `noindex` сохранён; её ресурсы и ссылка на главную используют пути от корня домена.

Обложка шеринга — `assets/images/share-card-v5.png`, PNG 1200 × 630. Заголовок: «Екатерина Крайнюк — тренер по триатлону». Описание: «Ну что, погнали? Плавание, велосипед, бег и триатлон — с удовольствием. Тренировки в Москве и онлайн по всему миру». Метаданные доступны в исходном HTML без выполнения JavaScript.

Разрешение индексации не подтверждает появление страницы в поиске. После приёмки DNS/HTTPS можно подтвердить основной домен в Google Search Console и Яндекс Вебмастере и отправить карту сайта `https://ekaterinakrainiuk.ru/sitemap.xml`. Токены этих сервисов добавлять только из соответствующего аккаунта, не выдумывать.
