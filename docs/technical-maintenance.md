# Проверки, публикация и восстановление

Технический регламент принят 5 октября 2026 года при закрытии согласованных пяти пунктов долга. Дизайн, тексты и набор услуг не пересматриваются. Применимые правила: UX-18, UX-20–22, UX-26, UX-31–32.

## Команды

- `npm ci --ignore-scripts` — установить закреплённый Playwright. На опубликованной странице npm и Playwright не используются.
- `npx playwright install chromium webkit` — установить тестовые браузеры; в Linux CI используется `--with-deps`.
- `npm run assets` — заменить версии CSS, JS, SVG, шрифтов, видео и субтитров на первые 12 символов SHA-256 их содержимого. Зависимости обрабатываются прежде потребителей, поэтому изменение шрифта обновляет ссылку в CSS, а затем версию CSS в HTML. Основная страница, 404, CSS и создаваемые скриптами SVG используют один механизм. Внешние URL, фотографические `srcset` и обычные якоря сохраняются.
- `npm run check` — проверить локальные пути, все корневые CSS и их импорты, SVG ID, актуальность версий, HTML, метаданные, висячую пунктуацию, синтаксис пяти скриптов и модульные тесты Python/Node.js. Неизвестный SVG ID, пропавший файл и цикл импортов дают ошибку.
- `npm run test:browser` — подготовить `_site/ekaterinakrainiuk/`, запустить локальный HTTP-сервер и браузерные сценарии по настоящему префиксу Pages.
- `npm run verify` — обновить версии и выполнить обе группы проверок. Затем включить изменённые ссылки в коммит и выполнить `git diff --check`.

Проверка ссылок рассчитана на текущие обычные HTML-атрибуты, CSS `url()` / `@import` и литералы `assets/…` в JS. Если в проекте появятся другие способы подключения ресурсов, нужно расширить общий парсер и его регрессионные примеры, а не обходить проверку. Динамические имена SVG дополнительно проверяются после реального обновления Таро в браузере.

## Браузерные сценарии

Восемь сценариев запускаются в Chromium 1440 px, Chromium 390 px и WebKit 390 px; отдельные шаги меняют ширину на 320 px и обратно на 1440 px.

1. Переход из навигации, положение заголовка относительно шапки, активный пункт, фокус, история браузера и прямая ссылка в спортивную историю.
2. Меню с клавиатуры, удержание Tab внутри открытого меню, Escape, переход к спорту, снятие `inert` и возврат видимого фокуса при смене ширины.
3. Ручная тема, сохранение после перезагрузки, тема на 404 и следование системной настройке.
4. Отсутствие автозапуска и `preload="none"` во всех движках; отсутствие ранних MP4-запросов в Chromium. Настоящий запуск одним нажатием, переключение звука, загрузка субтитров, размеры декодированного кадра и сохранность двух плееров, воспроизведения и фокуса при смене ширины проверяются во всех движках.
5. Открытие и пересдача Таро, актуальные SVG-символы, загрузка фотографии и шрифтов.
6. Раскрытая услуга и контакт без горизонтального переполнения при 320 px в обеих темах.
7. Навигация, услуги, нативные плееры и системная тема при отключённом JavaScript.
8. Читаемость текста отзывов при 320, 760, 980 и 1440 px, а также при размере корневого шрифта 200% на узком экране. Два времени при нехватке ширины выстраиваются вертикально, строки остаются в своих границах.

Ошибки скриптов и HTTP-ошибки локальных ресурсов останавливают сценарии. MET Norway заменяется неполным ответом: автоматический проход не зависит от внешнего сервиса и использует предусмотренный запасной режим. Субтитры включаются через стандартный TextTrack API, после чего проверяется настоящая загрузка и разбор VTT. Нативное меню выбора субтитров этим не проверяется. `reducedMotion` включён для повторяемости; полная анимация и физический iPhone требуют отдельного просмотра при изменениях в этих областях.

По [стандарту HTML](https://html.spec.whatwg.org/multipage/media.html#attr-media-preload) `preload` — рекомендация браузеру, которую он вправе не выполнить. В Linux WebKit наблюдались MP4-запросы до активации; сам запрос ещё не доказывает загрузку всего файла или автозапуск. Поэтому отсутствие ранних запросов — отдельная проверка Chromium, а отсутствие автозапуска и работоспособность настоящего видео обязательны для всех движков. Нативные `src` сохраняются и для работы без JavaScript.

При ошибке CI сохраняет `test-results/` и `playwright-report/` на 7 дней: скриншот, trace и описание шага. Не добавлять автоматические повторы или увеличивать таймаут ради скрытия воспроизводимой ошибки; сначала отделить дефект сайта от ограничений среды.

Chromium запускается в полном headless-режиме (`channel: chromium`); минимальный headless shell не используется. В macOS WebKit полный обход нативных элементов выполняется Option+Tab, в Linux CI — Tab. Настройки системы и пользовательского Safari не меняются. Найденная при смене ширины ошибка WebKit `ResizeObserver loop completed with undelivered notifications` устранена переносом записи размеров шапки в следующий кадр: измерение не меняет наблюдаемый layout внутри самого уведомления.

Также исправлена потеря фокуса, когда браузер успевает скрыть мобильное управление темой или настольный пункт до события смены ширины. Шапка запоминает свой последний фокус и переносит его на видимое управление; явный уход в содержание или клик за пределами шапки сбрасывает эту память. Тест проверяет оба направления смены ширины и сохранение фокуса в содержании. У локального тестового сервера увеличена очередь соединений: параллельная загрузка ресурсов не должна приводить к сбросу CSS-запросов и ложным ошибкам интерфейса.

## Публикация

Workflow запускается для `main`, `codex/**`, pull request и вручную. В CI `npm run check` не исправляет файлы: устаревший хеш блокирует выпуск. Подготовленный артефакт проверяется браузерами до загрузки в Pages. Job `deploy` имеет `needs: check`, права `pages: write` и `id-token: write`, работает только для `main` и окружения `github-pages`. Ветка окружения также ограничена `main`.

Процесс основан на [официальной схеме GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). В настройках репозитория источником выбран GitHub Actions. При неуспешном `check` опубликованная редакция остаётся прежней.

После выпуска сравнить SHA коммита с публичным `/release.json`, дождаться успешного `deploy`, проверить изменённые файлы по хешам манифеста и пройти затронутое действие на публичном сайте. Для исключения кеша использовать отдельный параметр запроса. Манифест доказывает совпадение файлов, а не визуальную приёмку или соответствие всем правилам UX.

## Точка восстановления

Тег `restore/2026-10-05-before-tech-debt` указывает на `58c273780d46f9c8cd479e417fd94e89877a2d20` — одобренную редакцию до технического выпуска. Исходные видео также остаются в этом Git-снимке.

Для отката создавать обычный обратный коммит в новой `codex/…` ветке, не переписывать опубликованную историю. Сохранить действующий workflow и инструменты проверки, восстановить необходимые публичные файлы из тега, выполнить `npm run verify`, проверить diff и опубликовать через `main`. Полное возвращение репозитория к старому тегу потребовало бы отдельного решения о настройке Pages: в том снимке ещё нет нового deploy job.
